# ICT 엔진 — XAUUSD

crowcode(Crow Concept)와 **별개의 패키지**다. 전제가 다르다.

| | crowcode | ict |
|---|---|---|
| 시간 기준 | UTC 세션 | **뉴욕 시간** (킬존·매크로) |
| 진입 근거 | 오더블록/FVG | **PD Array** (FVG, OB, 브레이커, BPR, iFVG) |
| 구조 전환 | CHOCH | **MSS + 변위(displacement)** |
| 목표 | 반대편 유동성 | **DOL** (Draw On Liquidity) |
| 방향 | HTF 구조 + Wyckoff | 유동성 습격 → MSS |

---

## 1. ICT 2022 모델 — 순서가 전부다

```
1. 유동성 습격    반대편 스톱을 먼저 턴다 (SSL 습격 → 매수 관점)
2. MSS + 변위     습격 뒤 구조가 깨지고 FVG 를 남긴다
                  ★ 갭을 남기지 못한 돌파는 전환이 아니다
3. PD Array 복귀  그 변위가 남긴 FVG/OB 로 되돌아올 때 진입
4. 프리미엄/디스카운트  매수는 레인지 하단, 매도는 상단에서만
5. 목표           반대편 미회수 유동성 (PDH/PDL/PWH/PWL/EQH/EQL)
```

손절은 습격 극점 바깥. 진입은 킬존 안에서만.

```bash
python3 -m ict signal --csv XAUUSD_M5.csv        # 최신 봉 셋업
python3 -m ict setups --csv XAUUSD_M5.csv        # 구간 전체 셋업
python3 -m ict backtest --csv XAUUSD_M5.csv --trades
```

```
[ICT2022] 매도  2024-01-11 19:40  (SilverBulletPM)
  진입 1955.43  손절 1959.88  목표 1942.07   RR 1:3.0  리스크 4.45
  진입근거 FVG 1955.22~1955.64
  유동성 습격 EQH 1959.62
  · 레인지 위치 70% (프리미엄)
  · OTE 구간
  · 변위 4.1×ATR
```

## 2. 먼저 할 일 — 개념 검증

**코드를 믿기 전에 데이터에 물어봐야 한다.** ICT 가 말하는 것들이
XAUUSD 에서 실제로 성립하는지 8가지를 측정한다.

```bash
python3 -m ict study --csv XAUUSD_M5.csv --since 2018-01-01
```

| 측정 | 무엇을 판별하나 |
|---|---|
| 1. 킬존별 당일 고·저 | "고점/저점은 킬존에서 만들어진다" — 50% 를 크게 넘어야 필터가 의미 있다 |
| 2. 전일 고·저 습격 | "가격은 PDH/PDL 을 가지러 간다" |
| 3. 유다 스윙 | 런던 오픈의 가짜 움직임 빈도와 크기 |
| 4. FVG 메움 비율 | CE(50%) 진입이 타당한가 |
| 5. Power of 3 | 상승일에 시가가 저점 근처인가 (먼저 털고 올리는가) |
| 6. OTE 도달 | 62~79% 지정가가 체결되긴 하는가 |
| 7. 변위 MSS 이후 도달 | 3R 을 시장이 실제로 주는가 |
| 8. 요일별 변동폭 | 손절 폭 대비 목표가 나오는 요일 |

비율이 우연 수준(50% 근처)이면 **그 개념은 코드에서 빼는 게 맞다.**
합성 데이터로 돌리면 킬존 비율이 24% 로 나온다 — 세션 구조가 없으니 당연하고,
이 도구가 판별력을 갖는다는 뜻이다. 실제 금 데이터면 여기서 갈린다.

## 3. 데이터 준비 (MT5)

2018년부터의 M5 데이터가 필요하다. **회원님 MT5 에서 직접 받아야 한다** —
이 저장소에서 접근 가능한 무료 소스는 전부 막혀 있다.

### 받는 법 1 — MT5 / TradingView 내보내기 (권장)

세미콜론 구분 `Date;Open;High;Low;Close;Volume` 형식이면 그대로 변환된다.

```bash
python3 tools/tv_to_csv.py XAU_30m_data.csv --out xau_m30.csv --detect
```

`--detect` 는 서버시간 오프셋을 **데이터에서 추정한다**. 금 선물은 뉴욕
17~18시에 쉬는데, 그 휴장이 서버시간 몇 시에 오는지 세면 오프셋이 나온다.
직접 줄 거면 `--server-offset 2` (엑스네스 등 대부분의 MT5 브로커).

**여기가 틀리면 킬존이 통째로 밀린다.** 준 값과 추정값이 다르면 경고한다.

### 받는 법 2 — 바로 받기 (최근 구간만)

```bash
python3 tools/fetch_gold.py --interval 5m --out gold_m5.csv   # 최근 60일
python3 tools/fetch_gold.py --interval 1h --out gold_h1.csv   # 최근 730일
```

COMEX 금 선물(GC=F)이다. **XAUUSD 현물이 아니다.**

### 형식

```csv
time,open,high,low,close,volume
2018-01-02T00:00:00Z,1302.55,1303.10,1302.30,1302.85,120
```

MT5 기본 내보내기는 탭 구분에 `2018.01.02 00:00` 형식이라 변환이 필요하다.
변환기를 같이 넣어 뒀다:

```bash
python3 tools/mt5_to_csv.py 내보낸파일.csv --out XAUUSD_M5.csv --server-offset 3
```

`--server-offset` 은 **서버시간 − UTC** 다. 엑스네스는 겨울 2, 여름 3.
**이 값이 틀리면 킬존이 통째로 밀려서 결과가 전부 무의미해진다.**

### 용량

2018~현재 M5 는 약 60만 봉, CSV 로 30~40MB 다. 그대로 올리기 어려우면
`--since 2021-01-01` 로 구간을 줄이거나 M15 로 리샘플해서 주면 된다.

## 4. 모델 — 무엇을 켜고 무엇을 껐나

7개 모델이 전부 `ict/strategy.py` 에 있고, 같은 `Market` 위에서 돈다.
기본으로 켜진 건 **둘뿐**이다.

| 모델 | 정의 | 진입 | 상태 |
|---|---|---|---|
| `Unicorn` | 브레이커와 FVG 가 **겹치는** 자리 | 겹침 중간 | **켬** 2% |
| `TurtleSoup` | 풀을 뚫고 **종가가 되돌아온** 가짜 돌파 | 털린 레벨 | **켬** 2% |
| `TJR` | 스윕 → 변위 → **기원 오더블록** 되돌림 | 마지막 반대색 캔들 | 끔 |
| `OTE` | 변위 레그의 62~79% 되돌림 | 시장가 | 끔 |
| `JudasSwing` | PO3 — 세션 레인지를 털고 반대로 | 반전 FVG | 끔 |
| `ICT2022` | 습격 → 변위 MSS → PD Array 복귀 | FVG 의 CE | 끔 |
| `SilverBullet` | 뉴욕 10~11시 창 안의 FVG | 그 FVG 의 CE | 끔 |

같은 21년을 **M15 와 M30 으로 따로** 돌려서, 둘 다 통과하고 구간별로도

### 결과 (기본 2개 모델)

```
M30   +829.9R   4,260거래   기대값 +0.195R   최대낙폭 46.8R
M15   +704.2R   4,275거래   기대값 +0.165R   최대낙폭 45.0R
```

금은 진입가로 깊게 되돌린 뒤 가는 일이 잦아서, 본전 스톱이 결국 이길 거래를
먼저 털어낸다.

### 끈 모델을 다시 켜기

지운 게 아니다.

```bash
python3 -m ict plays                          # 각 모델의 채택/제외 근거
python3 -m ict backtest --csv X.csv --models TJR

```

MT5 에서는 `ICTGold-all-models.set` 을 불러오거나 `InpUseTJR` 등을 켜면 된다.

### TJR 에 대해

[TJR Trades](https://www.youtube.com/@TJRTrades) 가 공개적으로 설명하는
순서를 그대로 옮겼다. **영상은 보지 못했다** — 공개 문서로 정리된 규칙을
근거로 했다.

  1. HTF 편향 → 2. 명확한 유동성 → 3. 스윕: 꼬리가 뚫고 **종가는 다시 안으로**
  (봉이 열려 있는 동안은 스윕이 아니다) → 4. 구조 전환 →
  5. **기원 오더블록** 되돌림에 진입 → 6. 손절은 스윕한 꼬리 바깥 →
  7. 목표는 반대편 유동성

ICT2022 와 재료는 같고 진입 자리만 다르다 (CE vs 오더블록). 21년 전체로는
양수(+77.7R)지만 최근 세 구간이 음수라 기본에서 뺐다. 리스크 1% 는 그가
말하는 상한 그대로다.

## 5. XAUUSD 보정 — `ict/gold.py`

**이 계층이 없으면 코드는 반드시 틀린다.** 2018년 금은 $1,300, 지금은
$3,300 이다. "$2 이상 움직이면 변위" 같은 달러 상수는 2018년엔 너무 크고
지금은 너무 작다. 그래서 모든 임계값이 두 가지 상대값 중 **큰 쪽**이다.

- **ATR 배수** — 지금 이 시간대의 변동성 대비
- **bp** (가격의 1/10,000) — 가격대 자체 대비

```
같은 설정(displacement_atr=1.5, displacement_bp=8)이 내는 실제 변위 기준
  금 $1,300 → $1.04   (ATR 0.2 인 아시아 시간)
  금 $3,300 → $2.64
```

| 항목 | 값 | 뜻 |
|---|---|---|
| `displacement` | 1.5×ATR 또는 8bp | 이보다 작으면 변위가 아니고, 변위가 아니면 MSS 도 아니다 |
| `min_fvg` | 0.20×ATR 또는 1.5bp, **최소 스프레드의 2배** | 스프레드보다 작은 갭은 갭이 아니라 호가 잡음 |
| `equal_tolerance` | 0.15×ATR 또는 1.0bp | 동일 고저를 하나의 풀로 묶는 오차 |
| `stop_buffer` | 0.25×ATR 또는 1.5bp | 손절을 극점에서 얼마나 띄울지 |
| `max_entry_distance_atr` | 3.0 | 현재가에서 이보다 먼 지정가는 채워질 때쯤 근거가 죽어 있다 |
| `in_rollover` | 뉴욕 17~20시 | 금 롤오버 — 스프레드가 벌어지고 호가가 사라진다. **전 모델 무조건 스킵** |
| `spread_ok` | 스프레드 ≤ 손절폭의 15% | $0.25 스프레드면 손절 **$1.67 이상**(17핍)이어야 통과 |

프로파일 3종: `standard`(엑스네스 Standard, 스프레드 $0.25) ·
`raw`(로스프레드 $0.15) · `strict`(변위 2×ATR 요구).
`--profile raw` 로 고른다.

> 손절 20~25핍($2.00~$2.50) 은 `standard` 를 통과한다 (스프레드 비중
> 10~12.5%). 그보다 타이트하게 잡으면 엔진이 스스로 거른다.

### 왜 `engine.py` 가 따로 있나

모델마다 매 봉에서 구조·유동성·FVG 를 다시 훑으면 O(n²) 다. 25,920봉에
68초가 걸렸다. `Market.build()` 가 한 번만 계산하고 나머지는 이분 탐색과
캐시로 조회한다 — **같은 데이터가 1.03초**.

빨라지자고 미래를 보면 백테스트는 통째로 거짓말이 된다. 그래서
`tests_ict/test_engine.py` 는 잘라낸 시계열에 같은 질문을 던져
`last_mss` · `pools` · `fresh_fvgs` 가 **완전히 같은 답**을 내는지 확인한다.

### 왜 `sample.py` 가 따로 있나

균일한 난수 시계열에서는 킬존 모델을 검증할 수 없다 — 킬존이 다른 시간과
구별되지 않기 때문이다. `sample.py` 는 세션별 변동성 배수를 넣는다.

```
뉴욕 시간대별 평균 봉 크기 (시뮬레이션)
  00시 $0.67   런던 03시 $2.93   뉴욕 08시 $3.39   롤오버 18시 $0.39
```

**이건 시장이 아니다.** 배관과 규칙을 시험하는 시험대일 뿐이다.

## 7. MT5 에서 바로 돌리기

```
mql5/Experts/ICTGold.mq5                 -> MQL5/Experts/
mql5/Presets/ICTGold-default.set         -> MQL5/Presets/
mql5/Presets/ICTGold-conservative.set
mql5/Presets/ICTGold-turtlesoup-only.set
```

MetaEditor 로 컴파일 → 전략 테스터 → XAUUSD, **M5**, "모든 틱".
`InpServerGmtOffset` 만 브로커에 맞춘다 (엑스네스는 보통 2 또는 3).

살아남은 모델 3개와 각자의 계획:

| 모델 | 목표 | 보유 | 본전 이동 | 리스크 |
|---|---|---|---|---|
| TurtleSoup | 4.0R | 4시간 | 2.0R | 2% |
| JudasSwing | 3.0R | 3시간 | 1.5R | 2% |
| OTE | 1.5R | 4시간 | 안 함 | 1% |

`python3 -m ict plays` 로 각 값의 채택 근거를 볼 수 있다.

**뺀 모델**: ICT2022 · SilverBullet · Unicorn. 실측에서 근거가 없었다
(`ict/plays.py` 에 이유가 적혀 있고, `--all-models` 로 켤 수 있다).

### 이 숫자를 어디까지 믿을 것인가

목표R × 보유시간을 격자로 훑어서 골랐는데, 표본이 M5 60일이다.
**격자 1등을 그대로 쓰면 잡음을 고른 것**이라 주변 칸이 같이 양수인
'고원'의 중앙만 채택했고, H1 730일에서 방향이 반대인 모델은 뺐다.
그래도 계획을 고른 데이터와 성적을 잰 데이터가 같다 — 진짜 검증은
2018년부터의 M5 를 MT5 에서 내보내 다시 돌려보는 것이다.
