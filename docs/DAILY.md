# 하루 운영 절차

> 하루 10% 손실이면 멈춘다. 멈춘 다음 그날 매매와 차트를 다시 보고,
> 안 된 이유를 확인해서 고치고, 그다음에 재개한다.

이 규칙을 코드로 강제한 것이 **서킷브레이커**다.
핵심은 **자정에 저절로 풀리지 않는다**는 점이다. 사람이 복기하고 직접 풀어야 한다.

---

## 두 종류의 정지를 구분할 것

| | 일일 한도 (`max_daily_loss_pct`) | 서킷브레이커 (`hard_stop_loss_pct`) |
|---|---|---|
| 기본값 | 2~3% (프리셋별) | **10%** |
| 성격 | 그날은 쉰다 | 잠근다 |
| 해제 | 다음 날 자동 | **사람이 직접** |
| 목적 | 흔한 나쁜 날 | 뭔가 잘못된 날 |

일일 한도는 자주 걸린다 — 정상이다. 서킷브레이커가 걸렸다면 그날은
"운이 나빴다"가 아니라 "확인할 게 생겼다"는 뜻이다.

---

## 하루 흐름

### 1. 아침 — 잠겼는지 먼저 본다

```bash
python3 -m crowcode status
```

잠겨 있으면 봇은 **신규 진입만** 막는다. 열려 있는 포지션의 손절 이동·분할
청산은 계속 돌아간다 (관리까지 멈추면 손절이 안 옮겨져서 더 위험하다).

### 2. 장중 — 봇이 알아서 한다

```bash
python3 -m crowcode live --symbol XAUUSD --preset intraday --live
```

10%에 닿으면 스스로 잠그고 로그에 남긴다:

```
[2026-09-11T15:22:10] circuit_breaker trading_day=2026-09-11 loss_pct=10.4 loss=-520.0 trades=3
```

### 3. 잠긴 날 저녁 — 복기

```bash
python3 -m crowcode review \
    --journal state/journal.jsonl \
    --csv data/xauusd_m1.csv \
    --html state/review.html
```

`--csv`(MT5에서 내보낸 시세)를 같이 주는 것이 중요하다. 없으면
**최대도달·최대역행을 계산하지 못해 판정이 거의 무의미**해진다.

HTML 리포트에는 거래마다 캔들 차트가 그려지고, 진입·손절·목표선과
그 거래를 잡은 근거가 함께 나온다. "차트를 다시 본다"가 이것이다.

### 4. 판정을 읽는다

| 판정 | 뜻 | 손볼 곳 |
|---|---|---|
| 손절보다 더 크게 잃었다 | **전략이 아니라 체결 문제.** 갭·지표 급변·슬리피지 | 지표 시각 등록, 금요일 마감 차단, 브로커 |
| 손절만 털리고 목표로 갔다 | 진입은 맞았고 손절 자리가 노이즈 안이었다 | `sl_buffer_atr` 상향 |
| 방향이 틀렸다 | 진입 트리거가 아니라 상위 프레임 판단 문제 | `htf` 상향, Wyckoff 일치 필수화 |
| 충분히 갔다가 되돌려줬다 | 본절이 이르거나 분할이 멀다 | `breakeven_at_r`, `partial_at_r` 하향 |
| 목표 코앞에서 돌아섰다 | 목표가 시장이 주는 것보다 멀다 | `target_rr` 하향 |
| 레인지에서 끝났다 | 추세 없는 구간에 진입 | Wyckoff 국면 필터 강화 |

리포트는 편중도 잡아낸다 — "런던 세션 8건 중 7건이 비승리(88%), 나머지는 20%"
같은 식이다. 단순히 손실이 많은 쪽이 아니라 **나머지와 비교해서 유독 나쁜** 쪽을
찾는다. 거래가 원래 런던에 몰려 있으면 손실도 런던에 많은 게 당연하기 때문이다.

### 5. 고치기 전에 검증한다

제안을 **그대로 믿지 말고** 같은 데이터로 다시 돌려서 확인한다.

```bash
# 고치기 전
python3 -m crowcode backtest --csv data/xauusd_m1.csv --preset intraday

# 제안대로 바꿨을 때
python3 -m crowcode backtest --csv data/xauusd_m1.csv --preset intraday \
        --set sl_buffer_atr=0.5 --set partial_at_r=2.0
```

숫자가 나아지지 않으면 바꾸지 않는다. **표본 20건 미만이면 패턴이 아니라
우연일 가능성이 크다** — 리포트가 매번 표본 수를 같이 보여 주는 이유다.

### 6. 해제

```bash
python3 -m crowcode release --note "손실 5건 중 4건이 stop_hunted → sl_buffer_atr 0.3→0.5, 백테스트로 확인"
```

메모는 **필수다**(5자 이상). 이유 없이 풀 수 없게 만든 것이 이 장치의 핵심이다.
메모는 이력에 남아서 `status` 로 언제든 다시 볼 수 있다 — 같은 실수를
반복하는지 확인하는 유일한 방법이다.

## MQL5 EA 에서

같은 구조가 EA 에도 들어 있다.

| | 입력값 |
|---|---|
| 서킷 임계값 | `InpHardStopPct = 10.0` |
| 복기 강제 | `InpHaltRequiresReview = true` |
| 해제 | `InpUnlock = true` 로 두고 EA 재부착 → 다시 `false` 로 |
| 기록 | `InpWriteJournal = true` |

잠금은 터미널 전역변수 `CC_LOCK_DAY` 에 저장된다. F3(전역 변수 창)에서
직접 지워도 해제된다. 단말을 껐다 켜도 유지된다.

EA 가 남기는 `MQL5/Files/crowcode_journal.jsonl` 은 **파이썬 복기 도구가 그대로 읽는다**:

```bash
python3 -m crowcode review --journal "<데이터폴더>/MQL5/Files/crowcode_journal.jsonl" \
        --csv data/xauusd_m1.csv --html review.html
```

---

## 주의

- **10%는 큰 손실이다.** 거래당 1% 리스크라면 10연패, 또는 손절이 안 지켜졌다는
  뜻이다. 서킷브레이커가 자주 걸린다면 리스크%부터 낮춰야 한다.
- 복기 판정은 **힌트지 정답이 아니다.** 표본이 적으면 우연이 패턴처럼 보인다.
- 손실 난 날마다 설정을 바꾸는 것이 가장 흔한 실패 방식이다.
  바꾸기 전에 백테스트로 확인하고, 확인 못 하면 그냥 두는 편이 낫다.
